# 0004 — Power BI delivered as a PBIP project generated from code

**Status:** accepted

## Context

The dashboard is a central deliverable. A `.pbix` file is binary, cannot be reviewed in Git, and could
not be produced here without driving the Power BI Desktop interface. Power BI Desktop 2.157 was
installed and supports Power BI Projects (PBIP: TMDL semantic model, PBIR report).

## Decision

- Deliver a **PBIP project** in `powerbi/project/`, generated by `scripts/build_powerbi_project.py`
  from one specification (tables, measures, pages), so the model, the report and `measures.dax` cannot
  drift apart. A test checks that the committed files equal the generator output.
- The model reads the exported CSV files through a `DataFolder` parameter (Power Query needs an
  absolute path); the committed value is an explicit placeholder.
- Validate it for real: JSON schemas shipped with Power BI Desktop, opening and refreshing in Power BI
  Desktop, DAX queries through the local engine compared with the pipeline exports.

## Consequences

- Reviewable, versioned dashboard; reproducible from code.
- Users must set the `DataFolder` parameter (or regenerate a local copy with `--data-folder`).
- Older Power BI Desktop versions without PBIR/TMDL support cannot open the project; no `.pbix` is
  committed, and nothing is published to the Power BI service.
