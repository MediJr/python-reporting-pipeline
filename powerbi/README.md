# Power BI report

| Path | Content |
| --- | --- |
| `project/SalesPerformance.pbip` | Power BI project (open this file in Power BI Desktop) |
| `project/SalesPerformance.SemanticModel/` | Semantic model in TMDL: tables, relationships, measures, Power Query sources |
| `project/SalesPerformance.Report/` | Report in PBIR: 3 pages, 32 visuals, custom theme |
| `measures.dax` | The 24 DAX measures with their descriptions |
| `theme.json` | The report theme (also embedded in the project) |
| `validation/query_model.ps1` | Queries the open model through Power BI Desktop's local engine and saves DAX results |
| `validation/dax_results.json` | DAX results of the validation session (used by the tests) |

Everything in `project/` is generated by `scripts/build_powerbi_project.py`; do not edit it by hand.

## Model

| Table | Source file | Role |
| --- | --- | --- |
| Sales | `fact_sales.csv` | Fact table, one row per order line; holds the measures |
| Calendar | `dim_date.csv` | Date table (marked as date table on `full_date`), one row per day |
| Product | `dim_product.csv` | Product and category |
| Quality Checks | `quality_checks.csv` | Checks of the last pipeline run |
| Rejected Rows | `rejected_rows.csv` | Source rows excluded by the pipeline |

Relationships: `Sales[date_key]` → `Calendar[date_key]`, `Sales[product_id]` → `Product[product_id]`
(many-to-one, single direction). Auto date/time is disabled. Each table is loaded with
`Csv.Document(..., Encoding = 65001)` and typed with the `en-US` culture, so `1234.56` is read correctly
whatever the regional settings of the computer.

Measures (folders): **Sales** — Net Sales, Gross Sales, Discount Amount, Average Order Value, Discount
Rate, Category Share %, Product Rank; **Volume** — Orders, Units Sold, Active Customers, Cancelled Orders,
Cancellation Rate; **Profitability** — Gross Margin, Gross Margin %; **Comparisons** — Net Sales PM,
MoM Growth %, Net Sales PY, YoY Growth %, Net Sales YTD, Latest Month MoM %, Latest Month YoY %;
**Data quality** — Rejected Rows, Checks Passed, Checks Failed. Revenue measures count completed orders
only, like the pipeline.

## Pages

1. **Overview** — net sales, orders, units, average order value, gross margin %; net sales by month
   against the same month last year; net sales by category; product ranking; net sales by segment.
2. **Trends and comparisons** — latest-month growth vs previous month and vs last year, YTD, active
   customers, cancellation rate; monthly table with previous month, MoM %, previous year, YoY %; category
   share over time; gross margin % and discount rate by month.
3. **Data quality** — rejected rows, checks passed and failed; rejected rows by reason and source; the
   list of checks with expected and actual values.

Year, category and segment slicers are on the first two pages.

## Open the report

Requires Power BI Desktop with Power BI Project (PBIP) support; validated with version 2.157
(August 2026).

1. Run the pipeline, then generate a copy of the project that points at this clone's exports:

   ```powershell
   .venv\Scripts\reporting-pipeline.exe run --config config/pipeline.toml
   .venv\Scripts\python.exe scripts\build_powerbi_project.py --local
   ```

   (`python scripts/demo.py` does both.)
2. Open **`output\powerbi-project\SalesPerformance.pbip`** in Power BI Desktop.
3. Click **Refresh**. The project is stored without data, so visuals show *(Blank)* until the first refresh
   (Power BI shows a banner saying that tables have no data and relationships must be refreshed).
4. Optionally save as `.pbix` (*File* → *Save as*) to share a single file with data.

> **Do not open `powerbi\project\SalesPerformance.pbip` directly** unless you change its parameter:
> it is the versioned copy, and its `DataFolder` parameter is the placeholder
> `C:\CHANGE-ME\python-reporting-pipeline\output\powerbi` (Power BI only accepts absolute paths, and a
> path of the author's machine would be wrong on yours). Opened as is, the refresh fails with
> *"Impossible de trouver une partie du chemin d'accès 'C:\CHANGE-ME\...'"* / *"Could not find a part of
> the path"*. To fix it in Power BI: *Transform data* → *Edit parameters* → set `DataFolder` to the
> absolute path of your `output\powerbi` folder → *Apply changes* → *Refresh*.

## What was validated, and what was not

Done in the development environment (Windows 11, Power BI Desktop 2.157):

- the 38 report JSON files were validated against the JSON schemas shipped with Power BI Desktop
  (0 errors);
- the project was opened in Power BI Desktop; the model loaded with its 5 tables;
- a full refresh from the exported CSV files succeeded (5.7 to 11.9 s);
- the DAX measures were queried through the local engine and compared with the pipeline exports:
  **174 values, 0 differences** (row counts, totals, every month with previous month and previous year,
  categories, product ranks, latest-month growth, data-quality counts);
- the three pages were captured after refresh ([screenshots](../docs/images/powerbi-overview.png)).

Not done: no `.pbix` file was saved (it would require driving the Desktop interface and would contain a
data cache); nothing was published to the Power BI service (no workspace, gateway or scheduled refresh);
mobile layout, accessibility review and other Desktop versions were not tested.
